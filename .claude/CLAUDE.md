## Грабли, на которые уже наступили

- **Одно sqlite-соединение на все потоки роняет процесс целиком.** Не
  пятисотка, а `ERR_EMPTY_RESPONSE`: Flask и gunicorn обслуживают запросы
  параллельно, sqlite3 на это не рассчитан. Соединение берётся через
  `store.Pool` — своё на поток.
- **`callable(sqlite3.Connection)` возвращает True.** У Connection есть
  легаси-метод `__call__`. Различать соединение и фабрику только через
  `isinstance`.
- **FTS5 с `content='paragraphs'` не работает** при вычисляемой колонке
  `stem`: любой `COUNT(*)` по индексу падает на «no such column: T.stem».
  Таблица обычная, со своей копией текста.
- **Подпись к иллюстрации нельзя определять по первой строке блока.**
  Длинная подпись дотягивается до левого края. Смотреть надо на
  строки-продолжения.
- **Модель отдаёт термины глоссария в именительном.** Формы для подсветки
  подбирает `ru_stem.find_forms` на бэкенде — тянуть русскую морфологию в
  браузер незачем.
- **Vite собирается с `base='/static/dist/'`.** Flask обязан отдавать этот
  путь штатной статикой, иначе catch-all возвращает на ассеты index.html и
  браузер отказывается исполнять модуль с типом text/html.

## Переиндексация

Схема БД менялась несколько раз. При изменении `SCHEMA` или эвристик
`ingest.py` библиотеку надо перезалить целиком:

```bash
rm -f data/library.db*
.venv/bin/python ingest.py --pdf "$HOME/Downloads/Румер. История семьи по документам.pdf" --id rumer
.venv/bin/python ingest.py --pdf "$HOME/Downloads/Йосель Сегалов. Кандидат прав.pdf" --id segalov
```

## Что не проверено

- Деплой на сервер. Compose и Dockerfile написаны по образцу mlops-tutor, но
  ни разу не запускались; сеть `book_edge` не создана, в Caddyfile блока нет.
- Книги, кроме этих двух. Эвристики разбора PDF выведены на них, и на книге с
  другой вёрсткой главы могут не найтись. Начинать с `ingest.py --dry-run`.
- Сканы без текстового слоя: отклоняются по порогу в 500 символов, OCR не
  подключён.
