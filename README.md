# Book Tutor

Чтение и разбор книг, загруженных как PDF. Каркас взят из
[mlops_tutor](../mlops_tutor) — Flask со стримингом через SSE, цепочка моделей
с автоматическим fallback, React-интерфейс с чатом, озвучкой и тултипами.
Подача содержания устроена иначе.

В тренажёре по MLOps модель рассказывала из своей головы, а 11 тысяч строк
`curriculum.py` задавали ей рамку. Здесь источник истины — текст книги. Глава
целиком уходит в промпт, вопросы поперёк книг обслуживает гибридный поиск, и
во всех режимах действует одно правило: факты только из приведённого текста,
внешнее знание помечается явно.

## Режимы

| Режим | Что делает |
|---|---|
| **Чтение** | Текст главы со ссылками на страницы, подсказками к устаревшим словам и озвучкой |
| **Разбор** | Наставник видит главу целиком и отвечает по ней: что значит документ, почему автор делает такой вывод |
| **Проверка** | Вопросы по прочитанному, с указанием места в главе после каждого ответа |
| **Эпоха** | Быт, право и деньги времени: что такое ревизская сказка, сколько метров в сажени, что означало быть лишенцем |
| **Поиск** | Вопрос по всем книгам сразу. Ответ собирается только из найденных кусков, каждый факт со ссылкой на книгу, главу и страницу |

## Как устроен поиск

Гибрид из двух половин, и обе нужны. Замер на двух книгах архива:

| Запрос | FTS5 | Векторы |
|---|---|---|
| «как звали женщину, владевшую домом с аптекой» | мимо | нашёл «Хозяйку звали Сося Борухова» |
| «кого лишили избирательных прав» | 1 из 3 мимо | 3 из 3 в цель |
| «что случилось в 1919 году» | точно | размазал по соседним годам |
| «чем торговали в Петербурге» | нашёл Гороховую | ушёл в перечень источников |

Лексический поиск выигрывает на датах, именах и точных терминах, векторный —
там, где вопрос пересказан своими словами. Списки сливаются обратным ранговым
слиянием (RRF): нормировать bm25 и косинус к одной шкале пришлось бы подбором
коэффициентов под каждый корпус, а ранги сравнимы всегда.

Векторной базы нет намеренно. Две книги дают 637 абзацев, матрица эмбеддингов
на них весит 0,9 МБ и целиком лежит в памяти процесса; Qdrant с контейнером и
сетевым хопом начал бы окупаться тысячах на ста абзацев. Векторы хранятся
BLOB'ами в той же SQLite, что и текст, так что библиотека — это один файл.

Русская морфология снимается snowball-стеммером: `unicode61` в FTS5 её не
знает, и без теневой колонки с основами запрос «дом» не находит «дома».
Словообразование стеммер не берёт — «лишили» и «лишение» остаются разными
основами, для этого нужен лемматизатор.

Плотный поиск всегда возвращает топ-K, поэтому у векторной половины есть
косинусный пол. На этом корпусе осмысленные вопросы дают максимум 0,49–0,68,
посторонние 0,16–0,40; порог 0,45 режет посторонние, кроме «рецепта борща»,
который дотягивает до 0,55. Полной защиты порог не даёт, поэтому в промпте
отдельным правилом стоит «не тяни ответ за уши».

## Как разбирается PDF

Нужен текстовый слой; сканы без распознавания отклоняются с явной ошибкой.
Разбор идёт на `pdftotext -layout`, который сохраняет отступы вёрстки.

Главы режутся по разрывам страниц: шапка главы — это две-три коротких строки
по левому краю без точки на конце. Подписи к иллюстрациям отделяются от
основного текста по отступам строк-продолжений: у абзаца вторая строка
садится на нулевую колонку, у подписи сдвинута. По первой строке судить
нельзя — длинная подпись растягивается на всю полосу и тоже начинается с
левого края.

## Запуск

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env    # вписать ZHIPU_API_KEY или OPENROUTER_API_KEY
.venv/bin/python ingest.py --pdf "путь/к/книге.pdf" --id mybook
cd frontend && npm install && npm run build && cd ..
.venv/bin/python app.py
```

Открыть http://localhost:5003. Книги можно добавлять и прямо в интерфейсе,
кнопкой внизу боковой панели.

Нужен `pdftotext` (`brew install poppler`) и `ffmpeg` для склейки аудио.
Модель эмбеддингов (~120 МБ ONNX) скачивается при первой индексации.

### Разработка

```bash
.venv/bin/python -m flask --app app run --port 5003 --debug
cd frontend && npm run dev     # vite на 5175, проксирует /api на 5003
```

## Озвучка

```bash
.venv/bin/python narrate.py --book rumer --out audio/rumer
.venv/bin/python narrate.py --chapter 8 --out audio --voice female
```

Microsoft Edge TTS, движок сетевой: процессор не нагружается, модель качать не
надо, синтез идёт в 3,7 раза быстрее реального времени. Книга на 73 минуты
звучания рендерится минут за двадцать. Перед синтезом текст приводится в
читаемый вслух вид: дореформенная орфография в цитатах, римские века,
архивные сокращения (`ф. 333, оп. 9, л. 10 об.` → «фонд 333, опись 9, лист 10
оборот»).

Клонирование голоса сюда не подключено. XTTS даёт на M1 с GPU real-time factor
около 1,2, на машине без видеокарты уходит в 6–15, и час звучания превращается
в десять часов счёта.

## Модели

Цепочка с fallback при 429, 402, 404 и перегрузке провайдера (проверено
19.09.2026):

| Модель | Провайдер | Статус |
|---|---|---|
| `glm-4.7-flash` | Zhipu | бесплатно, своя квота |
| `glm-4.5-flash` | Zhipu | бесплатно |
| `nvidia/nemotron-3-super-120b-a12b:free` | OpenRouter | 262K контекста |
| `z-ai/glm-5.2:free` | OpenRouter | общий free-пул, отвечает через раз |
| `google/gemma-4-31b-it:free` | OpenRouter | общий free-пул |

Эмбеддинги локальные: у Zhipu на международном эндпоинте их нет («Unknown
Model» на все коды), у OpenRouter нужны купленные кредиты. Считает
`fastembed` моделью `paraphrase-multilingual-MiniLM-L12-v2`, 384 измерения,
~120 МБ ONNX, шестьсот абзацев за пятнадцать секунд.

## Структура

```
app.py           Flask: SSE-чат, поиск, глоссарий, озвучка, загрузка книг
llm.py           цепочка моделей, разбор стрима
prompts.py       режимы работы с главой
store.py         SQLite: книги, главы, абзацы, FTS5, векторы, заметки
retrieval.py     гибридный поиск и слияние рангов
ru_stem.py       русская морфология: основы, стоп-слова, формы терминов
ingest.py        PDF → главы и абзацы
embeddings.py    fastembed
narrate.py       озвучка глав
frontend/        React, собирается в static/dist
```
